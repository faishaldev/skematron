# Rules: apps/web (local schema viewer)

Read before changing anything in `apps/web/`. These rules add to AGENTS.md and never relax it.

## What it is

- A local, single-user, read-only viewer.
  - It has no login and no authorization, so it binds to `127.0.0.1` only.
  - Never deploy it, expose it on a network, or point it at production.
  - The SaaS and self-hosted dashboard described in AGENTS.md needs authentication and per-project authorization first.
- It runs on Next.js 16 (App Router, Turbopack), which differs from older Next.js versions.
  - Before writing Next.js code, read the docs bundled in `apps/web/node_modules/next/dist/docs/`.
  - `apps/web/AGENTS.md` is generated by `next dev`. Commit it, and do not edit it.

## Data and secrets

- Only `lib/server.ts` (which imports `server-only`) accesses the database. Pages and actions call `readDatabase()`; nothing else opens connections.
- Never send the connection URL, credentials, or errors that contain them to the browser, the logs or the HTML. Show the `source` label only.
- The viewer is read-only toward databases: introspection only. No apply step, no SQL execution from the UI, no writes to user databases.
- Its only writes are Skematron's own files: saved snapshots in `.local/snapshots`, or `SKEMATRON_SNAPSHOT_DIR` if set.
  - Snapshots are immutable and never overwritten.
  - They are verified against their checksum when loaded.

## Input

- Schema names and snapshot ids arrive in query strings and form fields. Validate them:
  - Names are checked by introspection, which fails with "Namespace not found".
  - Ids must match the pattern in `createSnapshotStore`, which also rules out path traversal.
- Put mutations in server actions (they are protected by Next's Origin check), never in GET routes.

## Code

- Domain logic stays in `@skematron/core` and `@skematron/adapters`. The app only composes and renders.
- Use server components by default. Add client components only when an interaction needs them.
- Logic worth testing goes in `lib/`:
  - It uses `.ts` imports and Node APIs only, so `node:test` can run it.
  - Its tests are `lib/*.test.ts`, run by `pnpm test`.
- `pnpm typecheck` runs `next typegen` and then `tsc` for the app. `next build` must keep passing.
